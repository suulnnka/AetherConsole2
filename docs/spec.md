## 1. 项目定位与设计原则

AetherConsole 2(下称 AC2)是一台运行在网页上的**梦幻主机(fantasy console)**,参照对象为 PICO-8 / TIC-80 / SFC / GBA。项目由两部分构成:

- **主机**:虚拟游戏机本体——显示管线、时序、输入、音频、BIOS、aJS 运行环境、卡带加载、存档;
- **工具链(五件先行)**:图像编辑器、字体编辑器、音频工作站、打包环境、模拟器即调试器;**代码编辑器暂缓**(T16)——游戏代码用任意文本编辑器写 `.ajs`,打包工具自动收集。

AC2 是 `../AetherConsole`(下称 AC1)的**重制版**。AC1 的教训(详见 §2)是规格太松:任意内部分辨率、卡带不设上限、游戏代码主线程裸跑、颜色三种模式并存、工具链缺代码编辑器与调试设备——最终成品"是一套渲染库,而不是一台游戏机"。AC2 的原则:

1. **像真机**:规格硬约束(分辨率、颜色、卡带容量、内存、帧时序全部定死),游戏在严格边界内创作,约束产生风格。
2. **aJS 环境**:游戏代码是标准 JS 源码,跑在主机注入的 aJS 环境里——只见主机 API、不见宿主能力(DOM / 网络 / 真实时间)。不搞字节码虚拟机、不设指令预算与内存上限(老板拍板 T6/T8/T9),性能靠调试设备"看得见",而非主机"卡脖子"。
3. **软硬分工**:主机提供两套图形模式——模式1 是"硬件级"精灵/地图合成器(性能由主机保证),模式2 是"固件级"光栅化库(点线面、纹理映射、任意旋转由主机原生执行);游戏(aJS)只负责逻辑与编排,**不负责逐像素计算**——无论游戏逻辑写得多重,图元绘制都有固件保底性能。
4. **工具链闭环**:图像/字体/音频编辑、打包、调试五件官方交付,产物直接对接卡带格式;代码编辑器**先不做**(T16)——代码即 JS 纯文本,任意编辑器可写,打包工具自动收集。
5. **文档先行**:本规格是唯一事实来源;§16 列出全部待拍板项,批准后进入开发,变更须走版本记录(§19)。
6. **先用 JS 实现**(T16):主机与工具链全部以**纯 JavaScript** 编写,浏览器直接运行、零/最小构建;不前置投资 TypeScript、框架与打包链,待跑通后升级另议。

## 5. 核心与时序

### 5.1 帧模型

```
1 帧 = 1/60s ≈ 16.67ms,全机唯一节拍:
  ① 输入采样    壳/调试设备把三路输入写入虚拟键位(60Hz)
  ② 游戏逻辑    aJS 执行 update() 回调(宿主 JS 引擎原生速度;性能纪律见 §12.4)
  ③ 绘制提交    aJS 调用模式1/模式2 API 提交本帧画面(固件原生执行)
  ④ 显示合成    固件合成最终 240×176 帧 → 输出
  ⑤ 音频推进    音序器走 1 帧;合成 400 样本(24kHz/60)→ μ律编码输出
```

- **固定步长,不追帧**:单帧超时表现为掉帧,主机不做任何补偿;虚拟调试设备实时显示帧耗时与预算占用(§13.6)。
- 暂停(系统级)时逻辑、音序器、输入沿检测一并冻结;恢复时 `update()` 不补帧。

### 5.2 游戏生命周期(aJS 侧)

```js
// 卡带主模块必须导出的生命周期(细节见 §12.5)
init()                    // 装载后调用一次:加载资源到 VRAM/ARAM、初始化状态
update()                  // 每帧调用:读输入、推进逻辑、提交绘制
```

异常处理:aJS 回调抛出未捕获异常 → 主机停机,保持最后画面,`onError` 上报壳/调试设备显示;不提供"继续运行"选项(错误必须修)。

### 5.3 内存与资源区布局(分段命名空间,无统一编址指针)

| 区域 | 容量(默认) | 内容 |
|---|---|---|
| aJS 堆 | **不设上限**(老板拍板 T9:"js 的内存你能限制住?????随便用") | 游戏逻辑的全部对象与数据,由宿主 JS 引擎原生管理 |
| VRAM | 256KB(T12:tile 改 8bit 直存后由 128KB 扩容) | 模式1:BG tileset ≤72KB + OBJ tileset ≤72KB + tilemap 池 64KB + 备用;模式2:帧缓冲 42240B + 位图池(~210KB);**两模式对 VRAM 的占用互斥,切换模式清空 VRAM** |
| ARAM | 32KB | 音色库、pattern、音轨序列 |
| OAM | 1KB | 128 项 × 8 字节精灵属性 |

- 卡带资源按需载入上述区域(装载 API 见 §12.5);卡带本体不直接编址,容量 256KB 与 VRAM 256KB 之间由游戏自行换页/换图(类真机 Bank 概念,但以 API 而非指针呈现)。

## 6. 显示系统

### 6.1 通用规格

- 逻辑分辨率 **240×176**,最终输出恒为此尺寸;整数倍缩放与上屏由壳完成,主机不管窗口。
- 全机唯一颜色空间:**ANSI/xterm 256 色**(下节);不存在真彩路径,不存在第二套调色板模式。
- 采样按缩放比**自适应**(T7,§6.4.4):放大/等比 → 最近邻(硬像素风);缩小 → 区域平均(大图缩小防走样、防闪烁);manifest 可整体覆盖,保持全机观感一致。

### 6.2 ANSI 256 色定义(固定,不可修改)

| 索引 | 内容 |
|---|---|
| 0–15 | 16 基本色(标准 xterm 值):#000000 #800000 #008000 #808000 #000080 #800080 #008080 #c0c0c0 #808080 #ff0000 #00ff00 #ffff00 #0000ff #ff00ff #00ffff #ffffff |
| 16–231 | 6×6×6 RGB 立方:每通道 6 级,取值 {0, 95, 135, 175, 215, 255};索引 = 16 + 36R + 6G + B(通道级 0–5) |
| 232–255 | 24 级灰:亮度 8 + 10×i(i = 0–23) |

- 帧缓冲、tile、精灵、位图、封面、字体渲染的最终色值一律为 1 字节 ANSI 索引;真彩 → ANSI 的量化工具由图像编辑器导入通道提供(§13.2)。
- **无调色板层**(老板定案 T12):全机不存在调色板的选择、分组与切换;tile、精灵、位图、帧缓冲的颜色一律为 8bit ANSI 索引**直接存储**,两模式像素格式完全统一(8bit 索引 + 1bit 透明)。
- **索引 0(纯黑)不兼任透明**;透明是独立的"不画"标志,不占用任何颜色(全透明机制见 §6.6)。

### 6.3 模式1:精灵模式(类 SFC 硬件层)

由主机固件原生合成,**性能恒定,与画面内容无关**(游戏不参与逐像素绘制)。

#### 6.3.1 层次与优先级

自下而上:BG0 → BG1 → 精灵(优先级 0/1)→ 精灵(优先级 2/3)。精灵优先级 0–1 绘制于两层 BG 之间,2–3 绘制于 BG1 之上;同优先级按 OAM 序,序号小者在上。

#### 6.3.2 tile 与 tileset

| 项 | 规格(老板定案 T12:无调色板,直接 ANSI 256) |
|---|---|
| tile 尺寸 | 8×8;每像素 **8bit ANSI 256 索引直接存储**(256 色任用,无调色板层) |
| tile 透明 | **独立 1bit 透明位**(单独位平面,与模式2 位图同一机制,§6.6) |
| tile 体积 | 每 tile 颜色 64B + 透明位 8B = **72B**;1024 tile = 72KB |
| BG tileset | ≤1024 tile(72KB);BG0/BG1 共用 |
| OBJ tileset | ≤1024 tile(72KB);8×8 tile 为基本单位,**16×16 精灵引用 2×2 tile 块**(索引取左上,固件自动展开) |

#### 6.3.3 背景(BG0 / BG1)

| 项 | 规格 |
|---|---|
| 层数 | 2 层,独立 x/y 滚动(亚像素滚动支持,0x100 = 1px?否——**整像素滚动**,寄存器 11bit 覆盖 ±2048px) |
| 地图尺寸 | 每层可配置:32×32 / 64×64 / 128×128 tile(条目数 ≤16384;tilemap 池 64KB:128×128×2B = 32KB/层,两层恰好) |
| 地图条目 | **2 字节**:tile 索引 10bit + 水平翻转 1bit + 垂直翻转 1bit + 保留 4bit(置 0,预留扩展;原调色板字段随 T12 撤销) |
| 硬件滚动 | 每层 x/y 偏移寄存器,支持地图回绕(wrap);**不支持**硬件旋转/缩放(那是模式2 的事) |

> 大于 128×128 的地图由游戏在 VRAM 中分区换页(经典 SFC 手法);地图编辑器(§13.2)支持超大地图的导出切片。

#### 6.3.4 精灵(OAM)

| 项 | 规格 |
|---|---|
| 数量 | OAM 128 项,**每扫描线最多显示 32 个**(超出按 OAM 序丢弃,调试设备可见丢弃计数) |
| 尺寸 | 每精灵独立声明:**8×8 或 16×16**(仅此两种,老板明确要求) |
| 属性(8 字节) | x(9bit,可部分屏外)· y(8bit)· tile(10bit)· 尺寸(1bit)· 翻转 H/V(2bit)· 优先级(2bit)· 保留位(原调色板组字段随 T12 撤销) |
| 帧动画 | 无硬件动画;游戏每帧改 tile 索引即成(惯例:动画序列表存游戏数据) |

#### 6.3.5 模式1 API 概要

```js
S.loadTiles(dst, cartSeg, off, n)      // 卡带段 → tileset(装载期;重写即"整批换色")
S.setMap(layer, x, y, w, h, entries)    // 批量写 tilemap(装载期/切图)
S.setTile(layer, x, y, entry)           // 单点写(运行期,少量)
S.scroll(layer, x, y)                   // 每帧滚动
S.setSprite(i, attr)                    // 写 OAM;S.hide(i) 隐藏
S.clear()                               // 清 OAM/滚动,帧首自动清 OAM(写回法,防残影)
```

### 6.4 模式2:光栅模式(固件光栅化库)

自由绘制模式:**所有图元由主机固件原生光栅化**,aJS 仅提交绘制调用与参数——性能解释见 §14。帧缓冲为 240×176 × 8bit ANSI 索引。

#### 6.4.1 绘制管线

```
几何提交(点/线/三角形/多边形/位图块,可带 UV 与变换矩阵)
   ↓ 仿射变换(平移/旋转/缩放/斜切,2×3 矩阵,矩阵栈)
   ↓ 裁剪(屏幕矩形)
   ↓ 光栅化(扫描线三角形;线为 Bresenham;位图为块搬运/旋转采样)
   ↓ 着色(纯色 / 纹理采样;透明位跳过写入,无混合)
   → 240×176 索引帧缓冲
```

#### 6.4.2 资源:位图与矢量

| 项 | 规格 |
|---|---|
| 位图 | **任意尺寸**;像素 = 1 字节 ANSI 索引 + **1bit 透明位**(位平面分离存储);255 色 + 黑全部可用——透明不是颜色,是独立的"不画"标志(§6.6,老板定案 T11:不做半透明) |
| 位图池 | VRAM ~84KB,游戏自行分配图集;装载期从卡带入池 |
| 矢量图 | 路径集合(折线/贝塞尔),闭合路径可填充(纯色或指向某位图纹理)或描边;填充即不透明、不填充即透明(**1bit,无半透明**);矢量在装载期由固件**光栅化为位图缓存**(1bit 透明),运行期当位图绘制——"光栅化后纹理映射"的路径之一 |

#### 6.4.3 图元清单(全部固件原生)

| 图元 | 说明 |
|---|---|
| 点 | 单像素写 |
| 线 | 线段,可带宽度(1–4px) |
| 矩形 | 描边/填充 |
| 三角形/多边形 | 扫描线填充;**面可带纹理**:三顶点各带 UV,仿射纹理映射(类 PS1);纹理即位图池中的位图,采样含 clamp/repeat |
| 位图块 blit | 不透明像素写入 / 透明位跳过(**仅此两种,无任何混合**,T11);可带旋转角、XY 缩放、翻转(**任意角度旋转**) |
| 矢量路径 | 填充/描边(经光栅化缓存,同位图) |
| 文本 | BIOS 字体或卡带字体,任意位置/颜色/倍率(§7.4) |

#### 6.4.4 变换与采样

- 全局 2×3 仿射矩阵 + 矩阵栈(push/pop),作用于除像素写外的一切图元;
- 旋转精度:角度 1/256 圆;
- **采样策略:按缩放比自适应**(老板 2026-10-26 补充定案:"根据原始图片的尺寸跟渲染到位置的尺寸……原始尺寸很大,那就没必要最近邻"):

| 绘制时的缩放关系 | 采样规则 | 理由 |
|---|---|---|
| 放大或 1:1(目标 ≥ 原图) | **最近邻** | 颜色原样照搬,放大出硬边方块——保住手绘像素的干脆观感,不产生新颜色 |
| 缩小(目标 < 原图) | **区域平均(box filter)** | 每颗目标像素取对应源区域内**全部**像素的平均色,再量化回最近 ANSI 色。缩小若用最近邻等于从源区域随机抽 1 颗、扔掉其余,细节变噪点且逐帧闪烁(走样)——大图缩小必须平均 |

- 旋转绘制同理:含缩小分量的旋转按源区域平均,含放大分量的旋转按最近邻;
- 卡带可在 manifest 用 `sampling: "auto" | "nearest" | "smooth"` 覆盖,**默认 auto**(即上述自适应);
- 固件可把缩小平均预生成为降采样链(mipmap)以提升质量与性能,属实现层决策,不影响 API 与观感承诺。

> **术语说明(应老板问 T7:"什么叫旋转采样?是抖动吗?")** —— 不是抖动,两回事:
> - **采样(sampling)** = 旋转/缩放一张图时,屏幕上每个像素反查"对应原图哪个位置、取什么颜色"的取色规则,按上表自适应:放大最近邻(硬像素)、缩小区域平均(防走样)。
> - **抖动(dither)** = 用现有颜色的网点疏密去模拟中间色调,本机用于**图像编辑器导入真彩 PNG 时的量化选项**(§13.2),与旋转无关。

#### 6.4.5 模式2 API 概要

```js
R.loadBitmap(id, cartSeg, off)          // 卡带 → 位图池
R.loadVector(id, cartSeg, off)          // 卡带 → 矢量 → 自动光栅化为位图缓存
R.clear(color?)                         // 清屏
R.setMatrix(m) / R.push() / R.pop()     // 变换
R.pset(x,y,c) / R.line(x0,y0,x1,y1,c,w) / R.rect(x,y,w,h,c,fill)
R.poly(pts, {color})                    // 纯色多边形
R.triTex(p0,p1,p2, uv0,uv1,uv2, tex)    // 纹理映射三角形(仿射 UV;纹理透明位镂空)
R.blit(id, x, y, {rot, sx, sy, flip})   // 透明位跳过写入;无混合(T11)
R.text(x, y, str, {color, scale, font})
```

### 6.5 模式切换规则

- 卡带在 manifest 中声明**默认模式**;装载即进入该模式,VRAM 清零。
- 运行期允许 `setMode()` 切换:**切换清空 VRAM 与 OAM**(类真机改模式),游戏需重新装载资源;禁止逐帧来回切(调试设备对高频切换告警)。
- 两模式均可用文本 API 与 BIOS 服务;音频/输入/存档与显示模式无关。
- 不存在"同帧混用两模式"——模式1 的层合成与模式2 的帧缓冲是同一输出通道的两种占据方式(混用列为非目标,§17)。

### 6.6 透明机制(只做全透明 · 老板定案 T11)

**不做半透明,只做全透明**(老板 2026-10-26:"不做半透明,只做全透明")。ANSI 256 调色板确实没有透明色——而这正是本设计的出发点:**透明从来不是一种颜色,而是"这个像素不画"的独立标志**。颜色空间(ANSI 256)只负责"画上去是什么色";透明负责"挡住写入、露出下层",两者正交,互不占用。

| 路径 | 全透明的实现 |
|---|---|
| 模式1 BG / 精灵(tile) | **独立 1bit 透明位**(与模式2 位图同一机制,T12 后全机统一):tile 像素 = 8bit ANSI 索引 + 1bit 透明,透明像素合成时不写、露出下层 |
| 模式2 位图 | **独立 1bit 透明位**(与颜色字节分离的位平面):blit 时透明位 = 1 跳过写入、= 0 写颜色;255 色 + 黑全部可用,没有任何颜色被"透明"身份占用 |
| 矢量 | 原生:路径填充即不透明、不填充即透明;光栅化缓存为 1bit 透明位图 |
| 文本 | 字形位图 0 位即不写(同位图) |

**帧缓冲永远只存实色**(每像素 1 字节 ANSI 索引);透明只存在于资源与绘制过程,画完的屏幕每个像素都是实打实的 ANSI 色——因此"ANSI 256 不存在透明色"与全透明机制完全不冲突。

**无半透明时代的"透明感"手法**(官方支持,编辑器内建工具):

| 手法 | 做法 | 适用 |
|---|---|---|
| **50% 棋盘抖动** | 两色交错网点,离眼看即"混合色" | 水面、影子、玻璃、鬼影——像素风经典,零成本;编辑器抖动笔刷(§13.2) |
| **整批换色**(模式1) | `S.loadTiles` 重写 VRAM 中 tile 的颜色字节——无调色板后的"调色板动画"等价物,成本较高,适合小批量/低频 | 天色渐变、状态变色 |
| **逐帧换图** | 预备多档深浅帧序列轮播 | 爆炸、消散、渐隐 |
| **错位交织** | 双层图块/精灵棋盘交错摆放 | 视觉混合、半遮罩 |

## 7. BIOS

### 7.1 启动流程

```
上电 → ① 启动特效(约 2.0s,任意键/点击可跳过)
     → ② 系统菜单(卡带列表;方向选择,A/Enter 启动,B 取消)
     → ③ 装载卡带 → 声明游戏 ID → 进入游戏(init)
游戏中:Start+方向左(或壳菜单键)→ 暂停浮层 → 返回系统菜单 / 重启卡带 / 存档管理
```

### 7.2 启动特效(开机仪式感 · SEGA 式,老板定案 T2)

参照 SEGA 开机的经典感受:**LOGO 动画与专属开机音效同步定格**,短促、有辨识度、不可跳过:

1. 全黑 0.2s;
2. "AETHERCONSOLE 2" LOGO 自屏幕深处由小放大飞入(带拖影,0.6s);
3. LOGO 定格瞬间,专属**开机 jingle** 响起(μ律合成:上滑音 + 三和弦收尾,约 0.8s),LOGO 同步闪白一次——即"声音与画面合到一拍"的 SEGA 式记忆点;
4. 保持 0.4s,渐隐进系统菜单(0.3s)。

- 总时长约 2.0s,**不可跳过**(SEGA 式仪式感;时长已压到最短,不构成等待负担);
- 特效由 BIOS 用模式2 自绘;jingle 走 BIOS 自有音色(ARAM 保留区),不占游戏通道;
- LOGO 美术与 jingle 配方在 M5 出三版候选供老板选用(本规格先约定节奏与形态)。

### 7.3 系统菜单

- **卡带列表**:32×32 封面网格(整数倍放大 2×)+ 游戏标题 + 游戏 ID;无卡带/坏卡带显示占位图与错误码;
- 按 ID 去重(同 ID 显示版本号高的);
- 操作:方向选择、A/Enter 启动、B 返回;
- 子界面:**存档管理**(按卡带列出/删除存档,见 §10)、**关于**(固件版本、帧率/内存规格)。

### 7.4 内置字体(12px 规格 · 老板定案 T1)

| 项 | 规格(T1:"在左边和下面可以入侵 2px,还是 12px") |
|---|---|
| 主字形区 | **12×12px**;字符步进 12px(一行 20 字符) |
| 入侵区(左) | 主字形区**左侧额外 2px**:字形可向左溢出,压入前一字符的步进间隔(紧排,如 "AV" 并置) |
| 尾部区(下) | 主字形区**下方额外 2px**:字形可向下溢出(下伸部 y/g/p 与下沿装饰) |
| 编辑网格 | 14×14 = 主区 12×12 + 左 2 入侵 + 下 2 尾部(字体编辑器三区着色区分,§13.3) |
| 行高 | 默认 14px(12px 主区 + 2px 尾部空间,下溢不压下一行);紧凑 12px 可选(下溢压入下一行,游戏自担);一屏默认 20 字 × 12 行 |
| 内置字符集 | ASCII 32–126(95 字形);中文等扩展字符集随卡带字体 |
| 覆盖 | 卡带可带 `font` 段整体替换(仅游戏内生效);**BIOS 界面恒用内置字体** |
| 存储 | 每字形 14 行 × 14bit = 28 字节 + 码点表;AFNT v2 格式(§11.4) |

> 与 AC1 字体编辑器的"主区 12×12 + 左 2 入侵 + 下 2 尾部(14×14 网格)"方案同构,v1 的字体资产与编辑经验可直接继承。

### 7.5 BIOS 系统服务(API)

```js

bios cartridges()/saveList(id) // 卡带与存档查询(菜单内)
bios.reset() / bios.exit()     // 重启卡带 / 回系统菜单
bios.print(...)                // 调试输出(虚拟调试设备控制台)
```

## 8. 音频系统

### 8.1 输出规格(老板定)

| 项 | 规格 |
|---|---|
| 采样率 | **恒定 24,000 Hz**(一切合成与采样播放的母时钟,全机不提供第二采样率) |
| 输出编码 | **8bit μ律(G.711 μ-law)**:内部 16bit 线性混音 → 软限幅 → μ律编码 → 输出流(24KB/s) |
| 通道 | 8 通道,每通道类型由卡带自由声明(波形 / 2op FM);通道数与类型装载期声明,运行期不可改 |
| 混音 | 16bit 线性累加 → 主音量(系统设置)→ 限幅;母线挂帧推进,每帧合成 400 样本 |
| 时钟 | 音序器与合成**挂 60Hz 帧**,系统暂停即停(无独立音频时钟,保证确定性) |
| 采样播放 | 支持卡带内 24kHz/8bit μ律采样块(音源采样)在任意通道播放(音色类型 = 采样器) |

> 24kHz 与 μ律是**输出规格**而非合成限制:合成内部用线性插值与 16bit 精度,只在最终输出级压 μ律;调试设备可旁听编码前的线性信号(§13.6)。

### 8.2 合成器(音色三族 · 老板定案 T13/T15)

音色库由多件乐器组成,每件属于三族之一(采样回放作补充):

**FC 系(PICO-8 族)**——**固定波形集共 8 种,不支持自绘**(T15):

| # | 波形 | 说明 |
|---|---|---|
| 1 | 正弦 SINE | 纯音、柔和 |
| 2 | 方波 SQUARE | 50% 占空比,经典 8 位底色 |
| 3 | 脉冲 PULSE | 占空比可调(12.5/25/50/75%) |
| 4 | 锯齿 SAW | 明亮,谐波全 |
| 5 | 三角 TRIANGLE | 圆润,常作 8 位"贝斯" |
| 6 | 噪声 NOISE | **白噪 / 粉噪可切**(白噪 = 长周期 LFSR;粉噪 = 白噪经 −3dB/倍频程滤波,听感更厚更柔)——颜色是噪声内部选项,不占波形席位 |
| 7 | 金属噪 METAL NOISE | 短周期 LFSR,金属/打击乐质感 |
| 8 | 采样保持 S&H | 随机阶梯(Sample & Hold),科幻/脉冲感 |

> #7/#8 为凑足 8 种由 AC2 补选(老板:"再加两种,补充为 8 种吧");备选可换阶梯三角、锯齿+噪声混合等。

FC 系参数:**ADSR 包络、filter(截止/类型,可被 pattern FX 的 filter 替换,§8.3)、滑音旋钮(glide)、颤音 LFO(速率/深度)、音量**;脉冲另有占空比。

**2op FM 族(世嘉 MS 系,YM2413/OPLL 风味)**——参数清单:

| 部分 | 参数 | 说明 |
|---|---|---|
| 载波(出声算子) | 电平(音量)、包络 ADSR、频率倍率 ratio | ratio = 1 即基频 |
| 调制器(塑形算子) | 电平(=调制深度)、包络 ADSR、频率倍率 0.5–8、反馈 0–7 | 调制包络决定亮度随时间演化;整数比出谐波,非整数比出铃音;反馈自调制出金属/噪声感 |
| 环形调制 | 开关 | 载波 × 调制器 ring mod,钟声/金属(T13) |
| 公共 | 滑音旋钮、主音量、颤音 LFO、键速感应(可选) | 载波管音量、调制器管音色——调音色主要调调制器 |

**模拟族** | TR-808 / TR-909 / TB-303:鼓件(kick/snare/hi-hat 开闭/clap/cowbell/tom…)电路仿真参数与 303 贝斯(saw/square、滑音、滤器包络)的仿真实合成器

**采样回放(补充)** | 卡带 μ律采样块引用 + 回放速率

**公共**(三族通用)| 包络 A/D/S/R、音量、音色内 filter(可被 pattern FX 的 filter 替换)、颤音/滑音

> 模拟族在钢琴卷帘中按**鼓件映射**(纵轴每个音高格对应一件鼓);303 为有音高的单复声贝斯。

### 8.3 音序数据(三级:音色 / pattern / music · 老板定案 T13)

| 级 | 内容 | 存储 |
|---|---|---|
| 音色 | §8.2 三族乐器参数表,至多 64 件 | ARAM |
| pattern | **64 步**(固定 4/4 拍,每步 = 16 分音符,共 4 小节,**拍号不可改**);**每 pattern 绑定一件乐器,单复声**;数据 = 钢琴卷帘音符(音高/步位/时值)+ 音量轨 + **2 条 FX 轨** | ARAM |
| music | **8 条音轨**(对应 8 通道),pattern 拖入音轨排列成曲;**bpm 与 swing 为整曲共有属性**(全局,不逐轨);BGM 循环/跳转点;SFX 为单 pattern 由代码触发 | ARAM |

**pattern 的 FX 系统**(2 条 FX 轨,位于音量轨下方;每条 FX 设**起始步与结束步**,区域内音符受其影响):

| FX 类 | 变体 |
|---|---|
| 音高 | LFO / 向上滑 / 向下滑 / 滑至下一个音 |
| 音量 | LFO / 淡入 / 淡出 |
| filter | LFO 或方向(**替换音色本身的 filter**:不叠加,后设者生效) |
| 琶音 | 方向与速率 |
| 脉冲宽度 | LFO 或方向(仅对 PULSE 波形有效) |

### 8.4 API 概要

```js
A.playTrack(n) / A.stopTrack()          // BGM 级(音轨)
A.playSfx(n, {ch?})                     // SFX 级;可临时借用空闲通道,结束自动归还
A.ch(ch).set('volume', v)               // 通道实时控制
A.ch(ch).note(freq, len)                // 通道直驱(不用序列,适合程序化音效)
```

- SFX 借道规则:SFX 可抢占 BGM 声部,抢占结束自动恢复(沿用 AC1 已验证设计)。

## 9. 输入系统

**单人**;主机维护唯一一套虚拟键位状态与光标状态,三路设备(键盘/手柄/鼠标)由壳映射写入(§9.4)。

### 9.1 虚拟键位(共 7 键 + 光标)

| 虚拟键 | 键盘 | 手柄 | 鼠标 |
|---|---|---|---|
| 上/下/左/右 | 方向键 **或 WASD** | 十字键 | — |
| A(主键) | **Z 或 J** | **A 键**(亦见 R 肩键) | **左键** |
| B(副键) | **X 或 K 或 Space** | **B 键**(亦见 L 肩键) | **右键** |
| Start | **Enter** | Start | — |

- 键位映射沿用老板原话:"zx(or jk,k 再映射一个 space)"→ Z/J 同为主键,X/K 同为副键,**Space 绑定到副键 B**(老板定案 T3)。
- 手柄仅 A/B 两个动作键;**R 肩键同 A、L 肩键同 B**(老板定案 T4)。无 Select 键。
- 无"改键"功能(非目标 §17);以上即固定映射。

### 9.2 双查询视图(同一状态,两个语义)

```js
// 手柄视图
pad.a / pad.b / pad.start / pad.up / pad.down / pad.left / pad.right
      // 均含 .down(按住) .pressed(刚按下) .released(刚松开)

// 鼠标视图
mouse.left / mouse.right                // = A / B
mouse.x / mouse.y                       // 绝对位置(240×176 坐标系,可屏外)
mouse.dx / mouse.dy                     // 本帧相对移动增量(原始位移,不裁剪)
```

- **绝对与相对两种 API 并存**(老板要求):点选/光标类玩法读 `x/y`;视角/手势类玩法读 `dx/dy`。
- 键状态沿检测(pressed/released)由主机逐帧结算,游戏无需自行记上一帧。

### 9.3 手柄细则

- 十字键 → 虚拟方向(**左摇杆不映射**,老板仅要求"上下左右映射键盘");
- **右摇杆 → 鼠标**:摇杆位移转换为 `dx/dy` 相对增量送入鼠标状态(光标由游戏自行积分,或游戏读 dx/dy 直接用);
- A/B(+R/L 映射)、Start;其余手柄按键忽略。

### 9.4 采集职责

键盘/鼠标/手柄的物理采集、坐标转换(客户区 → 240×176)、手柄摇杆死区由壳/虚拟调试设备完成,按 60Hz 每帧一次写入主机 `pushInput()`;主机内不碰真实设备 API(便于嵌入与自动化测试)。

## 11. 卡带格式

### 11.1 总则

| 项 | 规格 |
|---|---|
| 扩展名 | `.aec`(AetherConsole Cartridge) |
| 容量 | **压缩后 ≤ 262,144 字节(256KB)硬上限**,打包环境强制检查,超限拒绝出品 |
| 容器 | 自定义二进制:头部 + 段表 + 段(段各自压缩,见 §11.3) |
| 出品格式 | **标准**(源码明文 + 段级 DEFLATE)或**混淆**(整卡混淆压缩,可选出品,防提取;非加密,T14)——头部标志区分,主机均可装载(§13.5) |
| 完整性 | 头部含 32bit CRC;BIOS 装载时校验,坏卡带在菜单报错码 |

### 11.2 容器布局(草案,M6 定稿二进制偏移)

```
.aec =
┌ 头部(64B):magic "AEC2" · 格式版本 · 游戏 ID(8B) · 游戏版本(2B)
│            标题(32B UTF-8) · 默认显示模式 · 段数 · 整卡 CRC
├ 封面段(1024B,恒不压缩):32×32 × 1B ANSI 索引 —— BIOS 直接零解压读
├ 段表(每段 16B):类型 · 压缩标志 · 压缩后长度 · 原始长度 · CRC
├ code 段    aJS 源码(文本,老板定案 T6:卡带内嵌源码;aJS 即 JS,无字节码;DEFLATE 压缩)
├ tiles 段   BG tileset / OBJ tileset(8bit ANSI 索引 + 1bit 透明位平面,双 tileset 一段或分两段)
├ maps 段    tilemap(条目流,可多张)
├ bitmaps 段 模式2 位图/图集(索引 + 透明位平面)
├ vectors 段 矢量资源(路径集合)
├ audio 段   音色 / pattern / 音轨 / μ律采样块
├ font 段    可选,AFNT 自定义字体
└ data 段    游戏自由只读数据(表、对话文本等)
```

### 11.3 压缩

- 段级压缩,算法 **raw DEFLATE**(v0.9:浏览器 `CompressionStream` 与 Node 内置同款、零自研实现、压缩率高于 LZ4;装载端 `DecompressionStream` 流式解压入内存);
- 对已高熵的段(μ律采样,有时含 aJS 源码)压缩比 <5% 时自动放弃压缩只置标志位;
- 封面段恒不压缩(§11.2);
- 打包环境输出**预算报告**:各段压缩前后体积、占比、与 256KB 的余量(§13.5)。

### 11.4 字体格式(AFNT v2)

码点表(u32 LE × n)+ 每字形 **14 行 × u16 位图(14bit 有效)= 28B/字形**(主区 12×12 + 左 2 入侵 + 下 2 尾部,§7.4);字体编辑器产出。

## 12. aJS(AetherJS):游戏代码运行环境

### 12.1 定位(老板定案 T6/T8/T9)

aJS = **跑在 AC2 主机 API 环境里的 JavaScript 源码**——语法就是标准 JS,由宿主 JS 引擎直接执行,**不编译字节码、不设指令预算、不设内存上限**("js/ajs 编译完了不还是 js?????"、"不需要指令预算. 随便用"、"js 的内存你能限制住????? 随便用"——老板 2026-10-26)。要点:

1. **环境注入而非虚拟机**:游戏代码运行在主机构造的环境中,可见的全局只有主机 API(`S`/`R`/`A`/`pad`/`mouse`/`bios`/…),没有 DOM、网络、文件、真实时间等宿主能力;隔离的具体实现(作用域注入 / 受限执行上下文)为实现层决策;
2. **不设枷锁**:无指令预算、无堆上限——性能纪律靠"看得见"而非"卡脖子":虚拟调试设备实时显示帧耗时分解与超帧率(§13.6),超帧**只告警不停机**;
3. **时间与随机**:主机 API 只提供 `frame()`(帧计数)与 `rng(seed?)`(可设种子),不提供真实时钟与系统随机;游戏遵守此约定时,输入录制回放(§13.6)可逐帧一致;
4. **卡带内嵌源码**(T6):code 段即 `.ajs` 文本(DEFLATE 压缩),装卡即执行,任何文本编辑器都能直接读懂卡带里的游戏。

### 12.2 工具链形态

- 源文件 `.ajs`;**代码编辑器(§13.1)负责编辑 + 即时检查**(语法错误、API 误用、异步用法告警),**不产出任何中间产物**;
- 打包环境只做源码收集(DEFLATE 压缩)入卡,无编译步骤。

### 12.3 语言与帧模型(T5)

- **语言 = 标准 JavaScript**(宿主引擎支持的全部语法;无自定义子集、无方言扩展);
- **帧模型 = 单帧同步**:`update()` 在一帧内同步返回。经查 AC1 全部 11 款游戏(8188 行)**零 `async`/`await`/`Promise`/`.then`**(老板预判"应该不用吧"正确,T5);官方模板与示例卡带全部同步写法;
- 因此 **async/Promise 不禁止、不保障**:引擎允许写,但异步回调不受帧时序约束(可能在两帧之间触发),官方工具链对其**告警不报错**;长任务的正解是游戏自行切片(状态机),官方文档提供范式;
- 禁用项(环境不提供,而非语法禁止):DOM / 网络 / 存储 / 真实时间 / 系统随机。

### 12.4 性能纪律(代替"执行预算")

| 项 | 规格 |
|---|---|
| 硬预算 | **无**(老板拍板 T8/T9:指令、内存均随便用) |
| 可见性 | 虚拟调试设备:帧耗时分解(逻辑/合成/音频)、超帧率统计——**只告警不停机** |
| 官方基准 | M3 交付基准套件(粒子/满 OAM/满屏旋转 blit),供游戏自测目标手感 |
| 唯一硬约束 | 帧模型本身:60fps 固定步长不追帧(§5.1)——单帧干不完就是掉帧,创作者自己看得见 |

### 12.5 主机 API 暴露

`S`(模式1)/ `R`(模式2)/ `A`(音频)/ `pad` `mouse`(输入)/ `bios` / `save` `load` / `frame()` `rng(seed?)` —— 全部为冻结对象,不可增删改;API 总表随 M1 起以 `docs/api.md` 维护(本规格只定概要)。

### 13.2 图像编辑器(像素画,三模式:老板定"精灵绘制 / 地图绘制 / 自由绘制")

### 13.3 字体编辑器(工具形态参考 AC1 迭代 · 老板定案 T13)

- **在 AC1 字体编辑器基础上迭代**(14×14 网格方案同构,规格见 §7.4),补齐 AC2 差异(ANSI 256 显示色等);
- 14×14 编辑网格 = **12×12 主字形区 + 左 2px 入侵区 + 下 2px 尾部区**,三区着色区分;
- 上下文预览条:实时渲染相邻字符展示入侵/尾部溢出效果;行高/基线参考线;
- 内置 BIOS 默认字体(ASCII 32–126)为起点;可添加任意码点(中文、假名、符号);
- 试排工具(输入样文看整体观感);导出 AFNT v2(§11.4)。

### 13.4 音频工作站(三件套:音色 / pattern / music · 老板定案 T13)

**① 音色编辑**——音色库管理(≤64 件),每件乐器属于三族之一(族规格见 §8.2):

| 族 | 编辑内容 |
|---|---|
| PICO-8 族(FC 系) | **8 种固定波形选择,不支持自绘**(T15):正弦/方波/脉冲/锯齿/三角/噪声(**白/粉可切**)/金属噪/采样保持;ADSR、filter、**滑音旋钮**、颤音 LFO、音量;脉冲占空比 |
| 2op FM 族(世嘉 MS 系) | 双算子面板(参数见 §8.2 FM 清单):载波/调制器各自的电平、ADSR、频率倍率;调制反馈;**环形调制**开关;滑音旋钮、主音量 |
| 模拟族 | **TR-808 / TR-909 / TB-303 仿真实合成器**:808/909 鼓件电路参数(tone/decay/snappy 等,逐鼓件一件音色)、303 贝斯(波形/滑音/滤器包络) |

键盘试奏;**输出经 24kHz→μ律 完整链路**,所闻即所得。

**② pattern 编辑**——**横向钢琴卷帘**(纵轴音高、横轴步进;老板定:"要搞横向界面的,键盘卷帘门这种"):

- **64 步 = 4 小节 × 16 分音符;拍号固定 4/4,不可改**(老板定);
- **每 pattern 选定一件乐器,单复声**(同一时刻至多发一音;同轨新音截断旧音);
- 卷帘下方三条横向轨道:**音量轨 + FX 轨 ×2**(FX 轨在音量轨下方,老板定);
- FX 类型(§8.3 表):音高(LFO/向上/向下/滑至下一个音)、音量(LFO/淡入/淡出)、filter(LFO 或方向,**替换音色内 filter**)、琶音、脉宽(LFO 或方向);每条 FX 圈定**起始步 → 结束步**,区域内的音符受其影响;
- 模拟族乐器:卷帘纵轴按**鼓件名映射显示**(§8.2);
- **试听:选定 BPM 播放当前 pattern**;步进输入 + 键盘实时录制。

**③ music 编辑**:

- **8 条音轨**(= 主机 8 通道);**pattern 拖入音轨**横向排列成曲(复制/移动/循环段);
- **bpm 与 swing 为 music 级共有属性**(整曲统一,不逐轨设置,老板定);
- 整曲试听(挂 60Hz 帧推进,与主机一致);导出 audio 段。

工作站公共:电平表/频谱示波器(μ律解码后显示);μ律采样块导入(外部 wav → 24k 重采样 → μ律)。

### 13.6 虚拟调试设备(模拟器即调试器 · 老板定案 T14)

## 14. 性能预算与风险

### 14.1 性能模型(为什么 60fps 可行)

- 模式1:合成全部固件原生,成本恒定(预计 <2ms/帧),游戏侧零像素成本;
- 模式2:图元固件原生;满屏不透明 blit 目标 <1ms、满屏旋转 blit <3ms、5k 纹理三角形 <5ms(240×176 小屏的红利;blit 无混合,透明仅"跳过"判断,T11;**目标值,M2 以实测表格替换本行**);
- 游戏逻辑:aJS 由宿主 JS 引擎原生执行,无解释器开销(老板拍板取消虚拟机与预算,T6/T8/T9)——AC1 经验:同类体量的像素游戏,逻辑开销远低于帧预算;
- 音频 8 通道合成 400 样本/帧,目标 <1.5ms。

### 14.2 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 模式2 图元在低端机超预算 | 中 | 图元实现 typed-array 向量化;调试设备帧耗时分解让游戏侧自控 |
| 256KB 容量对游戏内容偏紧 | 中 | DEFLATE + 位图 RLE + 音频 μ律本就紧凑;预算报告早期暴露;大图引导用 tile/矢量 |
| async/事件循环误用破坏帧时序 | 低 | 编辑器与调试设备对异步用法告警(§12.3);官方模板与示例全同步 |
| 多编辑器工程量大 | 高 | 分里程碑交付(§15),共用组件(取色器/播放内核/撤销栈) |
